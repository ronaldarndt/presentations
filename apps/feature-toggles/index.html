O que são feature toggles

Feature = funcionalidade

Toggle = interruptor

Ferramentas e técnicas que permitem ativar ou desativar funcionalidades sem precisar fazer deploy do sistema.

Deploy sem feature flag

              flowchart LR
                  A[Dev] --> B[Revisão]
                  B --> C[Teste]
                  C --> D[Merge]
                  D --> E[Deploy]
                  E -.-> F{Deu algo muito errado?}
                  F -->|Sim| G[Revert correndo]
                  G --> A
                  style E fill:#ff4081,color:#fff

Deploy com feature flag

              flowchart LR
                  A[Processo dev] --> E["Deploy (feature desativada)"]
                  E --> F[Ativa feature para os devs]
                  F -.-> G{Deu algo muito errado?}
                  G -->|Sim| H[Desativa feature]
                  G -->|Não| I[Ativa feature para 10% dos usuários]
                  I -.-> J{Deu algo muito errado?}
                  J -->|Sim| H
                  J -->|Não| K[Ativa feature para todo mundo]
                  K -.-> L{Deu algo muito errado?}
                  L -->|Sim| H
                  L -->|Não| N[Sucesso]
                  style F fill:#ff4081,color:#fff

Possibilidades

  • Ativar/desativar funcionalidades rapidamente
  • Testes A/B
  • Rollouts graduais
  • Selecionar quais usuários tem acesso a cada funcionalidade
  • Permite mergear funcionalidades incompletas

O que não são feature toggles

Chave especial do Secullum RH

Chaves especiais não são exatamente feature toggles, mas sim preferências de usuário.

São específicas para uma empresa e o usuário pode ativar/desativar.

Feature toggles são controlados por nós.

Tipos de flags

Tipo Descrição Vida Exemplo
Flag de release Ativa ou desativa funcionalidades até o lançamento oficial Curta pagina-registros
Flag de experimento Teste A/B, geralmente com métricas para avaliar o impacto Média mostrar-dark-mode
Flag operacional Controla aspectos operacionais do sistema Potencialmente longa usar-novo-servidor-cache , desligar-calculo-pesado
Flag de permissão Controla o acesso a funcionalidades com base em regras Potencialmente longa desligar-chamada-por-video , beta-novo-site

Sobre implementações não locais

  • ✅ Permite alteração rápida
  • ❌ Dependem de rede
  • ❌ Podem ter latência
  • ❌ Podem falhar
  • ❌ Podem sobrecarregar o servidor de features

Sobre implementações não locais

  • Cache
    • E se ficar desatualizado?
    • E se ficar inconsistente entre instâncias?
    • E se for limpo do nada? (thundering herd)

Sobre implementações não locais

Se o serviço cair? 💀

  1. Crashar a aplicação
  2. Usar valor padrão local
  3. Usar valor no cache
  4. Ignorar a feature

❌ Não é possível (de forma fácil) criar flags que controlam o ambiente e/ou coisas fora do código.

Alguns exemplos são:
  • Versão do .Net
  • Configurar qual migration do banco usar

Pegadinhas e limitações

  • "Débito de flags"
  • Flags de ambiente
  • Complexidade de teste

Conforme a quantidade de flags aumenta, a complexidade de teste cresce exponencialmente devido ao número de combinações possíveis entre elas.
