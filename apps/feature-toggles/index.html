O que são feature toggles

Feature = funcionalidade

Toggle = interruptor

Ferramentas e técnicas que permitem ativar ou desativar funcionalidades sem precisar fazer deploy do sistema.

Deploy sem feature flag

                  D --> E[Deploy]
                  E -.-> F{Deu algo muito errado?}
                  F -->|Sim| G[Revert correndo]
                  F -->|Não| H[Sucesso]

Deploy com feature flag

              flowchart LR
                  A[Processo dev] --> E["Deploy (feature desativada)"]

                  K -.-> L{Deu algo muito errado?}
                  L -->|Sim| H
                  L -->|Não| N[Sucesso]

Possibilidades e tipos de flag

Tipo O que permite Vida Exemplo
Flag de release Mergear funcionalidade incompleta e liberar aos poucos, com rollout gradual Curta pagina-registros
Flag de experimento Teste A/B, com métricas para avaliar o impacto Média mostrar-dark-mode
Flag operacional Ligar e desligar partes do sistema em produção, na hora Potencialmente longa usar-novo-servidor-cache , desligar-calculo-pesado
Flag de permissão Escolher quem tem acesso a cada funcionalidade Potencialmente longa desativar-chat-video , beta-novo-site

O que não é feature toggle

Chave especial do Secullum RH

Chave especial é preferência de usuário. Vale para uma empresa e o próprio cliente liga ou desliga.

Feature toggle é controlado por nós.

Por que não fazer em casa

Um toggle caseiro começa com um if e termina virando produto:

  • Regra composta: hoje ||, amanhã &&?
  • Rollout por porcentagem que não sorteia de novo a cada request
  • Cache, invalidação e valor padrão quando a leitura falha
  • Histórico de quem ligou o quê, quando e para quem
  • Tela para quem não é dev mexer
  • Mesmo valor no backend, no front e nos outros serviços

Sobre implementações não locais

  • ✅ Alteração rápida, sem deploy e vale na hora
  • ✅ Uma fonte só. Todas as instâncias leem o mesmo valor
  • ❌ Dependem de rede
  • ❌ Podem ter latência
  • ❌ Podem falhar
  • ❌ Podem sobrecarregar a fonte

Sobre implementações não locais

Se o serviço cair? 💀

  1. Crashar a aplicação
  2. Usar valor padrão local
  3. Usar valor no cache
  4. Ignorar a feature

  • "Débito de flags"
  • Flags de ambiente
  • Complexidade de teste
  • Inconsistência entre camadas

Flag serviu o seu propósito mas ninguém removeu ela do código.

Flag Status

HabilitarEnvioAvisoEsquecimentoPonto 🔴 Em 16 arquivos de configuração, nenhum leitor

Formas de mitigar:

  • Revisões periódicas de código
  • Issues para rastrear a remoção de flags obsoletas
  • Data de expiração para cada flag com avisos

Conforme a quantidade de flags aumenta, a complexidade de teste cresce exponencialmente devido ao número de combinações possíveis entre elas.

Pegadinhas e limitações

  • "Débito de flags"
  • Flags de ambiente
  • Complexidade de teste
  • Inconsistência entre camadas

A mesma flag é lida no front e no backend. Cache diferente, deploy defasado ou sessão antiga deixam a tela liberada e a API negando.

Formas de mitigar:

  • Backend responde o valor da flag junto com os dados da tela
  • API recusa com um erro próprio de flag desligada e o front recarrega as flags em vez de mostrar erro genérico

Exemplos práticos

  • Área da Revenda
  • Seletor de servidor de banco
  • Telas escondidas no Secullum RH
  • IsDistributedCacheEnabled
